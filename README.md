# Reproducibility Code for Simulation and Real-Data Analyses

This repository contains the simulation programs, saved simulation results, and real-data analysis used to produce the tables and figures in the accompanying manuscript and Web Appendix. The methods are developed for a right-censored additive-risk mixture-cure model and include weighted estimating equations (WEE), an internal control variate estimator (ICV), an adaptive control variate estimator (ACV), and an EM comparator.

### Scenario labels

The labels `S1`, `S2`, and `S3` used by the R scripts correspond to the result-directory labels `pai1`, `pai2`, and `pai3`, respectively. In the saved result folders, `L` and `H` denote the low- and high-censoring settings, while `n300` and `n600` denote internal sample sizes of 300 and 600.

## File descriptions

### Simulation programs

- `armc_em_right.R` implements the EM estimator used by `compare.R`. It must remain in the project root when `compare.R` is run, unless its location is supplied through the `EM_CODE_PATH` environment variable.
- `compare.R` runs the Scenario 1 comparison of the EM, WEE, and Oracle-WEE estimators and produces replication-level results, summary tables, survival-function results, incidence summaries, and incidence-probability surface plots.
- `uncertainty.R` compares uncertainty-adjusted and naive ICV estimators as the size of the external sample varies. It writes raw and summarized results and produces SE/SD calibration plots.
- `addICV.R` runs the Scenario 2 simulations for the ICV estimator under the three incidence-probability settings (`pai1`-`pai3`).
- `addACV.R` runs the Scenario 3 and Scenario 4 simulations for the ACV estimator.

The directories `Scenario1/`, `Scenario2/`, `Scenario3/`, `Scenario4/`, and `uncertainty/` contain the saved outputs used for the manuscript tables and figures. Depending on the analysis, these include replication-level CSV files, summary CSV files, plots, and cluster log files.

### Real-data files

- `realdata/clinical.RData` contains the processed TCGA-BRCA clinical data and estrogen-receptor (ER) status data used in the analysis. The data were obtained through the `TCGAbiolinks` package and saved in advance; therefore, downloading the TCGA data is not required to rerun the included analysis.
- `realdata/realdata.R` contains the main real-data analysis. It generates the results reported in Table 5 and produces the Kaplan-Meier plot reported in Web Figure S2. Run this script from the `realdata/` directory so that it can locate `clinical.RData`. Its main outputs are `1.txt` and `kmplot.png`.

### Plotting programs

- `boxplot.R` generates Figure 3 from the Scenario 2 `pai1`, low-censoring, `n = 300` results. It locates the corresponding summary and replication-level CSV files automatically and saves both PNG and PDF versions of the boxplot in the project root.
- `bandwidth.R` performs the bandwidth sensitivity study and creates `MSEplot.png`, corresponding to Web Figure S1.

## Software requirements

The analyses require R and the following R packages:

```r
install.packages(c(
  "survival", "MASS", "lars", "iterators", "foreach",
  "ggplot2", "doParallel", "miscTools", "gridExtra",
  "survminer", "mvtnorm", "Matrix"
))
```

The MPI simulations additionally require the `Rmpi` and `doMPI` packages together with a working MPI implementation on the computing cluster. Installation of `Rmpi` is system dependent and normally requires access to the cluster's MPI libraries and headers.

## Parallel computation

The simulation workflow is designed for MPI-based parallel computation, with the exception of `realdata/realdata.R`, `boxplot.R`, and `bandwidth.R`. The MPI drivers are `compare.R`, `uncertainty.R`, `addICV.R`, and `addACV.R`; `armc_em_right.R` supplies the EM routines used by `compare.R`. The required R packages and an MPI environment must be available when these programs are run on a computing cluster.

For local parallel computation, the MPI backend can be replaced by the `doParallel` package while retaining the existing `foreach` workflow. In particular, the MPI cluster creation, registration, and shutdown can be replaced by the following pattern:

```r
library(doParallel)

n_workers <- max(1L, parallel::detectCores() - 1L)
cl <- parallel::makeCluster(n_workers)
doParallel::registerDoParallel(cl)

# Keep the existing foreach(...) %dopar% { ... } computation here.

parallel::stopCluster(cl)
```

Adjust `n_workers` to the number of CPU cores and amount of memory available on the local machine. `bandwidth.R` already uses a `doParallel` backend. For a nonparallel smoke test, `compare.R` supports `PARALLEL_BACKEND=sequential`, and `uncertainty.R` supports `PARALLEL_BACKEND=serial`.

## Running the analyses

Run the simulation scripts from the project root. The scripts use environment variables to select the setting, replication range, output directory, and random-number seed. The examples below use a POSIX shell; use the equivalent environment-variable syntax on other systems.

### Scenario 1

`compare.R` sources `armc_em_right.R` automatically. For example, the following command runs `pai1` under low censoring with `n = 300` and stores the output in the same layout as the included results:

```bash
SETTING_ID=S1-L-n300 \
OUTPUT_DIR=Scenario1/pai1/L-n300 \
REP_START=1 REP_END=500 \
PARALLEL_BACKEND=mpi \
mpirun Rscript compare.R
```

A small sequential test can be run before submitting the full simulation:

```bash
SETTING_ID=S1-L-n300 \
OUTPUT_DIR=work/compare-smoke-test \
REP_START=1 REP_END=10 BOOT_B=100 \
PARALLEL_BACKEND=sequential \
Rscript compare.R
```

### Uncertainty analysis

```bash
SETTING_ID=S1-L-n300 \
OUTPUT_DIR=uncertainty/L-n300 \
REP_START=1 REP_END=500 \
PARALLEL_BACKEND=mpi \
mpirun Rscript uncertainty.R
```

The allowed settings are `S1-L-n300` and `S1-H-n300`.

### Scenario 2

For example, run the `pai1`, low-censoring, `n = 300` setting with:

```bash
SETTING_ID=S1-L-n300 \
OUTPUT_DIR=Scenario2/pai1/L-n300 \
REP_START=1 REP_END=500 \
mpirun Rscript addICV.R
```

Use `S1`, `S2`, or `S3` in `SETTING_ID` for `pai1`, `pai2`, or `pai3`, respectively. Each incidence setting can be combined with `L` or `H` censoring and `n300` or `n600`.

### Scenarios 3 and 4

`addACV.R` uses setting labels `T1`-`T5`. The included Scenario 3 results use `T1`, whereas the included Scenario 4 results use `T2`-`T5`. Example commands are:

```bash
# Scenario 3
SETTING_ID=T1-L-n300 \
OUTPUT_DIR=Scenario3/T1-L-n300 \
REP_START=1 REP_END=500 \
mpirun Rscript addACV.R

# Scenario 4
SETTING_ID=T2-L-n300 \
OUTPUT_DIR=Scenario4/T2-L-n300 \
REP_START=1 REP_END=500 \
mpirun Rscript addACV.R
```

### Real-data analysis and plotting scripts

```bash
# Table 5 and Web Figure S2
cd realdata
Rscript realdata.R
cd ..

# Figure 3
Rscript boxplot.R

# Web Figure S1
Rscript bandwidth.R
```

Full simulation runs are computationally intensive. The replication range, bootstrap size where configurable, and number of workers should be reduced for preliminary checks.
